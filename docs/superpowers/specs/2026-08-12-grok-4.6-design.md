# Design: add Grok 4.6 Extra High as the curated Grok pick

**Date:** 2026-08-12
**Status:** Approved for planning
**Follows:** `2026-07-09-cursor-delegate-model-layer-design.md` (allow-list + single curated Grok effort id)
**Precedent:** `f2fad58` (four-surface menu sync; tests/spec/historical docs left alone)

## 1. Motivation

cursor-delegate curates one Grok effort id for plan-writing and strong coding. That id is currently `cursor-grok-4.5-high` (CLI label "Cursor Grok 4.5" — top of the 4.5 line; 4.5 has no Extra High).

Grok 4.6 is on the account menu. Unlike 4.5, 4.6 restored an Extra High tier:

| id | CLI label |
|---|---|
| `cursor-grok-4.6-high` | Cursor Grok 4.6 |
| `cursor-grok-4.6-xhigh` | Cursor Grok 4.6 Extra High |

The model-layer rule is: seed the **top** curated effort, not the similarly named `-high` slot. For 4.6 that is `cursor-grok-4.6-xhigh`. Callers that reason "`-high` is the strongest" would silently miss Extra High — the same booby trap the 2026-07-09 design called out for 4.5.

## 2. Decisions (locked)

1. **Add** `cursor-grok-4.6-xhigh` and `cursor-grok-4.6-high` to the allow-list. Labels `Grok 4.6 Extra High` and `Grok 4.6`, family `grok`. Extra High is the curated pick; `-high` is callable.
2. **Keep** `cursor-grok-4.5-high` on the allow-list. It stays callable; it is no longer the recommended Grok pick.
3. **Retarget** catalog + skill recommendations to `cursor-grok-4.6-xhigh`.
4. **Prices unchanged:** `$2` input / `$6` output / `$0.5` cache-read / `$0` cache-write per MTok (same as 4.5).
5. **Default unchanged:** `composer-2.5`.
6. **No TypeScript.** The `cursor_run` model enum is generated from `config/models.json` at startup.
7. **Four-surface cut only** (same as `f2fad58`): `config/models.json`, `config/agents/catalog.md`, `plugin/skills/delegate/SKILL.md`, `plugin/skills/delegate/reference.md`.

## 3. Allow-list (`config/models.json`)

Add two entries; do not remove or edit the 4.5 entry:

```json
"cursor-grok-4.6-high":  { "label": "Grok 4.6",            "family": "grok", "price": { "input": 2, "output": 6, "cacheRead": 0.5, "cacheWrite": 0 } },
"cursor-grok-4.6-xhigh": { "label": "Grok 4.6 Extra High", "family": "grok", "price": { "input": 2, "output": 6, "cacheRead": 0.5, "cacheWrite": 0 } }
```

`requireNonClaude` still keys off `family === "claude"`. All Grok ids remain valid for uncorrelated review.

## 4. Catalog and skill

**Recommendations** (every current `cursor-grok-4.5-high` *pick*) become `cursor-grok-4.6-xhigh`:

- Catalog **Re-implementer** row
- Catalog plan-writing note
- Skill “when to delegate”, model-picks table, example `cursor_run`, plan-writer step
- `reference.md` plan-writer default and the “never review Grok with Grok” example

**Allow-list prose** lists both 4.6 ids and 4.5 plus the existing composer / gemini / gpt ids. `cursor-grok-4.6-high` and 4.5 are documented as still valid, not as the plan-writer/coding pick. No new catalog role for either.

## 5. Testing and doctor

- Offline unit tests keep inline fixture ids (`grok-4.5-xhigh`). They inject their own map and do not load `config/models.json`.
- Live tests (`npm run test:live`) already load the bundled map; the new id is callable there with no test edits.
- `doctor` compares allow-list ids to `cursor-agent --list-models`. A missing `cursor-grok-4.6-xhigh` is a **warning**, not a hard failure (existing drift rule).

## 6. Out of scope

- TypeScript / resolver / schema-builder changes
- `spec.md` and `docs/superpowers/*` historical plans (already stale from the 4.5 rename and GPT-5.6 split)
- Unit-test fixture rewrites
- Other 4.6 variants (`-medium`, `-low`, `*-fast`)
- Price changes
- Removing 4.5 from the menu
